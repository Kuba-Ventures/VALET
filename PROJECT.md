## What it is  [rewrite when value prop evolves]

**The problem:** Talking to LLM chat boxes is slow, and stitching together Calendar, Mail, a browser, terminals and a coding agent to get one thing done is slower. Shipping that as a product also means no end user should have to paste in their own API keys.
**The solution:** A single voice loop on the Mac that routes intent — conversation, system lookup, research, file/app control, ship-to-Cursor — without leaving the orb, with all AI billed centrally behind a license so the download ships with zero vendor secrets.
**The user:** A macOS builder who lives in Claude Code, Cursor and the Apple suite and wants hands-free orchestration — and, post-Phase-2, a paying customer who buys a license and downloads a signed app.
**The value:** Sub-second voice for the simple stuff, full Opus + web tools for the hard stuff, native macOS control with a safety net — and a clean install with no key management.

## What's built  [rewrite]

### Stage A — Proxy spine (LIVE in prod)
- License-gated AI/TTS proxy in `product-site/` (Next.js on Vercel, https://jarvis-y.vercel.app). Routes: `app/api/proxy/{completion,research,tts,usage}` plus a native Anthropic-dialect `app/api/proxy/v1/messages`.
- Backed by `product-site/lib/proxy/{auth,pricing,usage,langfuse,anthropic,fish}.ts`. Anthropic + Fish keys live server-side; the downloadable app ships with no vendor secrets.
- Every call validated against the Supabase `licenses` table; usage metered per license (requests, tokens, est. cost) against a **per-plan** fair-use allowance (`FAIR_USE_USD_PRO` / `FAIR_USE_USD_ULTRA`, fallback `FAIR_USE_MONTHLY_USD`; #59). Behavior is still **soft-warn** because `FAIR_USE_MODE` defaults to `warn` — it never blocks until the owner sets `FAIR_USE_MODE=throttle`/`block`.
- Traced to Langfuse with the license as user id, payloads scrubbed by default.
- `product-site/supabase/migration_usage.sql` adds the `license_usage` table + atomic `record_usage()` RPC (30-day rolling, lazy reset). Zero new npm deps.

### Stage B — App repoint + license gate (LIVE)
- `server.py` routes all AI + TTS through the proxy: Anthropic SDK `base_url` → `{PROXY_BASE_URL}/api/proxy`, license in `X-License-Key` (`server.py:2930`); `synthesize_speech` → `/api/proxy/tts` (`server.py:2460`).
- `licensing.py` validates against `/api/license/validate` with a 7-day offline grace window (state in `data/license_state.json`); the assistant loop refuses when not entitled.
- App stores only `LICENSE_KEY` + `PROXY_BASE_URL`; in-app API-key entry removed. Settings now expose License Key + Proxy URL + a `test-license` action.
- Dev fallback (no `LICENSE_KEY` → direct keys) preserved for the internal repo only.
- Also extracted from `server.py`: `task_manager.py`, `voice_text.py`, `project_scanner.py`. The tightly-coupled voice-dispatch core (`voice_handler` + `_execute_*` handlers + lookups) was deliberately left in `server.py`.

### Stage C — Control layer (MERGED)
- Portable `action_executor.py` — `ActionExecutor` ABC + `ActionResult` + `Capability` enum (open app/path, read/write/move/delete file, list folder, run app command, send keystroke, navigate, run script).
- `applescript_executor.py` — macOS backend. Detects app scriptability via the bundle's `.sdef`/Info.plist without launching; non-scriptable apps return a structured, logged `not_supported`. Deletes go to Trash. Portable so a future Windows/Linux (or Accessibility/vision) backend is a swap.

### Stage D — Risk-tiered safety (MERGED)
- `safety.py` — `classify()` → Tier 0 (auto) / Tier 1 (confirm); `KillSwitch`; `ConfirmationManager`. Tier 0 = reads/lists/opens/navigate; Tier 1 = delete/move/overwrite, drive apps, keystrokes, scripts, bulk ops, protected paths. New-file write is Tier 0; overwrite is Tier 1.
- `safe_executor.py` — `SafeExecutor` decorator over the Stage C executor (confirm-first, Trash-safe, kill-aware).
- `server.py` routes `[ACTION:DELETE_FILE]` + raw `[ACTION:APPLESCRIPT]` through it.
- Frontend `confirmCard.{ts,css}` (holographic Allow/Deny card) + an always-available STOP kill-switch button.
- REST `/api/safety/{kill, kill/reset, status}` + WS confirm/kill round-trip.

### Stage K / UC1 — Universal control: Accessibility primitives (MERGED to main — #80)
First stage of the universal screenshot/AX control track (UC0 audit → UC1…UC6). Builds the general perception→action input layer **behind the existing `ActionExecutor`/`Capability` seam** — additive, AppleScript path untouched.
- **New control primitives** in `accessibility_executor.py` (rewritten from the K1 keyboard-only stub): `observe_ui` enumerates the focused window's AX tree (via `ApplicationServices` `AXUIElementCopyAttributeValue`) into a ref-addressable element list — `role`, `title/label`, `value`, `enabled`, `frame [x,y,w,h]`; `click_element(ref|point)` clicks via **AXPress where available, else a synthetic `CGEvent` mouse click** at the element centre; `key_combo("cmd+s")` posts modifier chords (US-keycode map); `send_keystroke`/`open_app` carried over. ### Stage K / UC3 — Click/type by natural-language description (MERGED to main — #83, landed via #87)
"Click on Submit" / "type my email in the address field" → a concrete, gated action — the sellable demo capability.

### Stage K / UC4 — Observe→decide→act loop (MERGED to main — #84, landed via #87)
The multi-step, demo-able capability: give Vee a small goal and it runs a supervised loop until done.
- **New `agent_loop.py`:** `run_loop(executor, goal, client, …)` — **observe** (UC2) → model **decides** the next single action via a **forced tool call** (`next_action` schema: click/type/key/open_app/done/fail — guarantees a valid action, no JSON-parse flake) → **execute** (UC1/UC3 primitives) through the safety gate → **re-observe** → repeat. Returns `{status, steps, history, message}` with status ∈ done/failed/vetoed/halted/capped. Defaults to **Sonnet** for the decide step (Haiku was too unreliable picking the right element step-after-step). Pure orchestration — drives the passed-in executor + client, emits via a caller callback.
- **Supervision foregrounded:** every observe/decide/act beat streams to the process panel (`emit_step`); each mutating step is gated (confirm card + kill switch — the user sees and can veto each step); a **hard step cap** stops runaways; a **veto (denied)** stops the task; the **kill switch** is checked every iteration; a failed action re-observes and lets the model adjust, bailing after 2 consecutive non-veto failures rather than looping blindly.
- **Wiring:** `server.py` `_run_ui_task` + `/api/ui/task` endpoint + a voice path — the LLM emits `[ACTION:UI_TASK] <goal>` for multi-step "do X then Y" UI requests, dispatched to `_handle_ui_task` on a background task (deadlock-safe per-step confirms).
- **Tests/validation:** `tests/test_uc4_loop.py` (6 headless — done-detection, hard step cap, veto-stop, kill-switch halt, stuck-recovery bail, honest model-fail; all pass). **Live on-device:** the loop ran a real 2–3 step TextEdit task end-to-end (type → cmd+a → done) under auto-allowed per-step confirms — actions executed and the model recognized completion. **Known caveat (focus):** synthetic keystrokes always go to the *focused* app; in a CLI test harness a terminal stole focus and the typed text landed there instead of TextEdit. In the real app driving a foregrounded target it lands correctly, and the per-step confirm keeps the user in the loop — but robust app-focusing before typing is a follow-up to harden. Pending on-device: live confirm-card/STOP click-through of a full loop in a running build (incl. the flagged "keep STOP visible during the loop" UI requirement from UC1).

### Stage K / UC5 — Interruptible / barge-in voice (MERGED to main — #85, landed via #87)
From the founding brief: talk over Vee, redirect, or stop mid-stream — not just wake-word + turn-based.
- **The core change is keeping the mic LIVE during TTS.** Today the frontend `pause()`s the mic while Vee thinks/speaks (so you could only barge in with the mouse STOP button). `main.ts` now keeps the recognizer running through `thinking`/`speaking`, and filters echo so Vee doesn't hear itself.
- **New `frontend/src/bargeIn.ts`:** pure `shouldBargeIn(heard, spoken)` — explicit interrupt words ("stop", "wait", "no", "actually", "cancel", …) always cut in; otherwise a transcript that mostly overlaps what Vee is currently saying is treated as echo and ignored; a substantive non-echo utterance barges in. `main.ts` tracks `currentSpokenText` (from the audio message's `text`) to feed the filter; on a real barge-in it stops TTS, sends a `barge_in` signal, then the new transcript.
- **Backend `barge_in` (server.py):** cancels the in-flight reply (`_cancel_response`) **and** the running UC3/UC4 loop/action task — **without latching the kill switch** — so the next utterance runs immediately (a redirect, not a dead stop). The loop/act tasks are now tracked per-WS (`_track_uc`) so they're cancellable; a fresh command also cancels a running loop (belt-and-suspenders). Handled inline on the WS receive loop (just flips a flag + cancels a task), so the loop never parks — the confirm-deadlock lesson re-verified.
- **Tests/validation:** `bargeIn` decision logic verified (10/10 cases: keyword interrupts, echo suppression, new-command vs echo, thinking-state). Frontend typechecks + builds; backend compiles; the 30 UC1–UC4 headless tests still pass. **Pending on-device (needs live speech):** the actual talk-over-TTS interrupt within ~1s and rapid interrupt/redirect — echo behaviour is mic/speaker-dependent and will need live tuning. **Scope note:** barge-in currently *cancels* the running loop and runs the new utterance fresh; injecting a correction into a still-running loop without restarting ("no, the other one" mid-step) is a refinement on top of this.

## Decisions log  [append-only — never rewrite or delete]

- **2026-06-15 — Account login provisions the license key + profile; don't add a second auth system (account-login PR A)** — Design in `docs/account_login_design.md`. Goal: log in once with account email+password → the app provisions the **license key** (no manual paste) **and** the profile (name/honorific/DOB/location). Discovery: the data layer **already exists** — Supabase email/password auth, the `licenses` table, and an `account_sync` table the app already pushes profile to via `/api/proxy/sync` (rendered on `/account`). The only missing capability is **turning a login into a license key**, so we build minimally rather than a new auth system. **PR A (product-site, this):** `getSupabaseAnon()` (anon client — the service-role admin client can't validate passwords); `loginAndProvision(email,password)` → `signInWithPassword` then reuse `getAccountLicenses` (prefer entitled) + `getLatestAccountSync().profile`; `POST /api/account/app-login` returning `{license_key, has_license, status, plan, profile}`; and `GET /api/proxy/profile` (X-License-Key) + `getProfileByLicenseKey()` for launch-time re-pull (mirrors `device-settings`). Password is used only for `signInWithPassword`, never stored/logged; the license key stays the bearer for every other call. **PR B (app, next):** login form in onboarding + Settings → write `LICENSE_KEY` to `~/Library/Application Support/VALET/.env` + populate the profile fields; launch-time re-pull; manual key entry kept as fallback. Web profile editor on `/account` deferred (app is the profile source-of-truth via sync-up). tsc clean; no JS test runner in product-site (runtime needs Supabase env).
- **2026-06-15 — STT provider: stay on Web Speech for now; measure finalization latency on the prod WebView before paying for a streaming provider (perceived-latency investigation, no code)** — Write-up in `docs/stt_provider_investigation.md`. Key findings: (1) **PR 0 doesn't actually measure STT finalization latency** — `t0` is *defined as* the STT-final, so the you-stop-talking→final gap is upstream and uncaptured; provided a ~5-line `onspeechend→final` instrumentation to capture it. (2) **Dev and prod use different speech engines** — Chrome/Google in dev, WebKit/WKWebView/Apple in the Tauri build — so any STT measurement or accuracy call must be made in the prod WebView. (3) Web Speech's reliability cost is already visible as workarounds: the entire `wakeWord.ts` mishearing vocabulary (incl. "hey vee"→"av" collapse) and `voice.ts` rapid-end backoff. (4) Cost/latency comparison grounded in current pricing: AssemblyAI Universal-Streaming ~$0.15/hr (~300ms, immutable transcripts, tunable endpointing) is the cheapest/lowest-latency option; Deepgram streaming ~$0.46/hr; both bill session duration, so you'd stream only during active capture. **Recommendation: don't switch on assumption** — Web Speech is free/zero-dep and PR 2 (push-to-talk) already sidesteps the worst mishearing + finalization-pause class at zero cost. Switch only if, after PRs 0–4 land and the instrumentation runs on-device, finalization median is ≳500ms AND accuracy still hurts despite PTT AND the per-user cost is acceptable — then pilot AssemblyAI behind the existing proxy/license pattern, flag-gated, keeping Web Speech as the free fallback.
- **2026-06-15 — Pre-warm + keep-alive the proxy connection; the per-call handshake was the hidden TTS tax (perceived-latency PR 4)** — Found the real, reliable TTS lever the PR-3 audit pointed at: `synthesize_speech` created a **fresh `httpx.AsyncClient` per call**, so every TTS request paid a full TLS handshake to the proxy — **~139ms median measured** (cold ~178ms vs warm ~39ms, against `valetvoice.vercel.app`) — and the Anthropic SDK paid it once on the first turn (both share the proxy host on the licensed path). Fixes: (1) a **shared keep-alive `httpx.AsyncClient`** (`_get_http_client`, pooled, connect-timeout 5s, keepalive 90s) used by `synthesize_speech`, closed in lifespan shutdown — handshake paid once per session, not per turn; (2) a best-effort startup `_prewarm` task that warms the proxy TLS connection (licensed path) **and** the Anthropic SDK→proxy connection + the static prompt cache via one `max_tokens=1` request (disable with `VALET_PREWARM=0`); (3) extracted `_static_system()` so the warm builds a **byte-identical** cacheable prefix → the first real turn gets a cache READ on the ~6–8KB static block, not a cold write. This **compounds with PR 1**: sentence-chunked streaming makes several TTS calls per turn, each of which previously paid its own handshake. Net: ~139ms off every TTS call after the first, and off the very first turn (model + TTS) via the pre-warm. Best-effort throughout — pre-warm never blocks or fails startup.
- **2026-06-15 — Make the Fish latency tier a usable, env-tunable knob — but don't flip the default on assumption (perceived-latency PR 3)** — Audited the TTS path. - **TOP RISK (now ADDRESSABLE, not yet closed) — shipped users bill the owner's personal keys with the cap in warn mode.** Every shipped user's AI + TTS runs through the proxy's single owner-held Anthropic + Fish keys. The per-plan fair-use mechanism now exists (#59) but `FAIR_USE_MODE` still defaults to `warn`, so it never blocks. With a signed build live, anyone with a license can drive unbounded spend until the owner sets `FAIR_USE_MODE=throttle`/`block` + the per-plan allowance envs in Vercel. **This is the single concrete step to close the risk** (see "What's left", item 2).
- **Mic-green permission detection is broken (backend).** `/api/permissions/status` returns null for Microphone, so the green indicator never lights even when mic is granted — in both onboarding and the new Console Permissions section. Needs a real mic/speech TCC authorization check via the bundled pyobjc.
- **The Universal Control track is on main but NOT in any signed build.** UC0–UC6 are all merged, but no signed/notarized DMG has been packaged with them, so downloaders have none of it yet. Shipping it also gates on open caveats: synthetic-input target-focus hardening (keystrokes follow keyboard focus), the live in-app passes (UC4 confirm/STOP, Screen-Recording grant/revoke UI, UC5 echo tuning), and the STOP-visible-during-the-loop UI fix. Ship UC1–UC3 first; hold UC4/UC6-terminal/UC5 until those clear.
- **Synthetic input follows keyboard focus (UC4).** Keystrokes land in whatever app holds focus — a stray terminal caught them in a CLI harness. Mitigated in the real app by per-step confirm + activating the target app, but robust app-focusing before typing is unbuilt. This is the headline reason UC4/UC6-terminal are held from the first signed build.
- **Stripe payouts are PAUSED.** Live mode is on and verified, but account activation is incomplete — live charges accrue in the Stripe balance and cannot pay out until the client adds a bank account.
- **Single-vendor TTS** — Fish Audio has no fallback; an outage takes voice down.
- **Soft fair-use + 7-day offline grace are intentionally lenient.** A canceled/abused license keeps working for up to 7 days offline; over-allowance never stops a request. Fine for a controlled launch, not for scale.
- **`restart_self` still lives in `self_mod`**, which is excluded from shipped builds — packaged restart relies on the watchdog relaunch; the in-app `restart_self` path stays broken until relocated.
- **Factory not yet functional end-to-end** — factory-review needs `CLAUDE_CODE_OAUTH_TOKEN` (repo has zero secrets) before it can pass.
- **Self-signed certs** require manual Chrome trust on first run; documented only as the openssl command.
- **Anthropic 529s** during the design turn previously forced an emergency model swap; no resilience layer added since.
