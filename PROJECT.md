## TL;DR  [rewrite]

> **VALET is superseded and no longer actively developed.** This summer the voice-agent work moved to **Telly**, which lives in [`Twin-Peaks-Labs/voice-agent`](https://github.com/Twin-Peaks-Labs/voice-agent) and is live (v0.7.12, shipping via Sparkle). New product work happens there, not here.

VALET (persona "Vee", a British butler) was the original voice-first macOS menu-bar assistant: hold ⌃⌥ from any app, talk, and it answers out loud and drives the Mac. Its commercial loop is still up: buy, sign in at valet-voice.com, download a signed DMG. The last public build is **VALET 0.2.44** (Latest on `Kuba-Ventures/valet-downloads`, 2026-07-20), and no product code has merged since. The Twin Peaks org items (#335 to #341) belong to Telly. What remains here is a wind-down: decide archive vs keep, and what happens to existing users, licenses, the download page and the hosted resources. The wind-down list lives in [`ROADMAP.md`](ROADMAP.md).

## What it is  [rewrite when value prop evolves]

**The problem:** Typing into LLM chat boxes is slow, and stitching Calendar, Mail, a browser, terminals and a coding agent together to get one thing done is slower. A shipped product also can't ask end users to paste in their own API keys.
**The solution:** One voice loop on the Mac that routes intent (conversation, system lookup, research, file and app control, guided walkthroughs, ship-to-Cursor) without leaving the orb. All AI is billed centrally behind a license, so the download ships with zero vendor secrets.
**The user:** A macOS builder who lives in Claude Code, Cursor and the Apple apps and wants hands-free orchestration; a paying customer who buys a license and downloads a signed app.
**The value:** Sub-second voice for simple things, Opus plus web tools for hard things, native Mac control with a safety net, real-time answers from keyless public data, and a clean install with no key management.

## What's built  [rewrite]

Everything below is on `main` and in the public v0.2.44 build unless noted. Per-release detail is in [`CHANGELOG.md`](CHANGELOG.md); history is in the Changelog section at the bottom.

**Frontend / UI**
- Tauri 2 menu-bar app (`ActivationPolicy::Accessory`, no Dock icon) with a white tray webview popover and an always-on-top, draggable Three.js orb (`src-tauri/src/main.rs`, `frontend/src/orb.ts`).
- Global held ⌃⌥ push-to-talk from any app, via a `CGEventTap` in the main Tauri process (`spawn_global_chord`); always-listening wake word is a toggle.
- Native click-through cursor-follower overlay, one per display, with a Clicky-style instruction bubble (#126, #136, #170 to #172).
- Voice-led violet onboarding: license or account login, permissions (mic, Accessibility, Input Monitoring, Screen Recording, Contacts), voice, profile (`frontend/src/onboarding.ts`).
- Settings split into User and Console tabs; holographic confirm card plus an always-available STOP kill switch (`frontend/src/confirmCard.ts`).

**Voice and Mac control (backend)**
- FastAPI backend (`server.py`) over WebSocket, bundled with PyInstaller. Claude Haiku for fast turns, Opus for research, Fish Audio TTS with two British voices.
- No-LLM fast path: app launch, Spotlight file search, System Settings deep links, tiered system actions (`app_index.py`, `file_index.py`, `settings_index.py`, `system_actions.py`).
- Universal Control: Accessibility read/click/type, screen perception with vision fallback, natural-language targeting, the observe-decide-act loop, barge-in, terminal and Cursor skills (`accessibility_executor.py`, `perception.py`, `target_resolver.py`, `agent_loop.py`, `skills.py`, `terminal_skill.py`).
- Guided walkthroughs, teach-don't-do: glide the cursor to each control, narrate, wait for the user (`walkthrough.py`).
- Compose-and-stop messaging for Messages, Gmail and Slack: VALET never sends to a person; the user presses send. Apple Clock control.
- Live information from keyless sources: ESPN sports, Yahoo Finance markets, Google News, DuckDuckGo Lite fast lookup, Open-Meteo weather (`sports.py`, `markets.py`, `news.py`, `weather.py`).
- Gmail day digest from inbox-row previews, signed-out recovery via guided login, save to Apple Notes as per-email cards with action items as Reminders (`inbox_digest.py`, `notes_access.py`, #295 to #329).
- Scroll actions and "scroll until you find X" (#317, #319); Deepgram STT for the push-to-talk turn only, falling back to the built-in recognizer (`deepgram_stt.py`, #320, #325).
- Risk-tiered safety: Tier 0 auto, Tier 1 confirm, kill switch (`safety.py`, `safe_executor.py`). Self-editing is disabled in shipped builds.
- Local memory in SQLite + FTS5 (`memory.py`); Calendar via EventKit merged with Google Calendar; Contacts read-only.

**Backend / data (`product-site/`, Next.js on Vercel)**
- License-gated AI/TTS proxy (`app/api/proxy/{completion,research,tts,usage,v1}`); vendor keys stay server-side. Usage metered per license against per-plan fair-use allowances (#59); mode defaults to `warn`.
- Supabase Auth accounts, `/account` dashboard (key, plan, usage %, download, Stripe Billing Portal), owner-only `/account/admin`, desktop-to-web sync, device settings Phases 1 to 3.
- Stripe live (Free / Pro $20/mo / Ultra $50/mo) under the Twin Peaks Labs account; payouts paused.
- Duplicate-license fix is on `main`: `upsertLicenseFromSubscription` upserts with `onConflict: "stripe_subscription_id"` (`product-site/lib/license.ts`), with `migration_dedupe_licenses.sql` and `migration_licenses_onconflict_fix.sql` (#220). Whether the migration ran in production is not recorded.
- Langfuse tracing with the license as user id, payloads scrubbed. Resend for license-key and auth email.

**Infrastructure**
- `packaging/build-macos.sh`: PyInstaller `--clean`, Tauri build, Developer ID signing (Team `QZX7VBLDZT`), notarization via the `valet-notary` profile. `packaging/deploy-local.sh` hot-swaps the backend with a re-sign (#309).
- Releases on `Kuba-Ventures/valet-downloads`; `product-site/app/api/download/route.ts` validates the license, then redirects to Vercel `DOWNLOAD_URL`.
- PR factory (`.github/workflows/factory.yml`): `factory-tests` and `factory-review` are required checks; `CLAUDE_CODE_OAUTH_TOKEN` is set; `FACTORY_AUTOMERGE` is unset (off).
- Branch protection on `main` requires up-to-date branches (`strict: true`) plus both factory checks.

## Decisions log  [append-only, never rewrite or delete]

- **2026-10-02, VALET is superseded by Telly**. Finley confirmed the voice-agent work moved this summer to Telly in `Twin-Peaks-Labs/voice-agent` (live, v0.7.12 via Sparkle). VALET stops active development; the Twin Peaks org items move to Telly's tracker (voice-agent #20, #25). Archive vs keep is still open, and nothing is archived yet.
- **2026-10-02, Twin Peaks picks PostHog over Langfuse for observability (#338)**. Recorded from the Twin Peaks issue; VALET still traces through Langfuse (`product-site/lib/proxy/langfuse.ts`) and nothing has been built yet.
- **2026-07-20 — The Gmail day-digest summarizes from inbox-row previews; it does NOT open each email (declined non-goal)** — The digest reads each inbox row's ~100-char sender/subject/snippet and summarizes across the day's mail; clicking into individual messages to read full bodies was **explicitly declined by Finley on 2026-07-20** ("I do not want this capability right now"). Rationale: coordinate-clicking each message proved fragile — window resize/duplication, wrong-account drift, and address-bar hits — while the row previews already carry enough signal for a useful spoken digest. Recorded as a deliberate scope boundary so it isn't re-opened as a TODO.
- **2026-07-20 — A signed-out Gmail inbox is recovered via guided login, not dead-ended; VALET never types the password (#326/#327)** — An account-scoped digest used to say "I don't see your inbox" when signed out — an instruction the user can't act on while logged out. Now `inbox_digest` distinguishes signed-out (Chrome is on Google's sign-in / chooser) from "no inbox open" by inspecting the page, returns a `signed_out` status, and `_handle_summarize_inbox` hands off to the #284 guided login, then re-runs the digest at the inbox (`allow_login=False` guards a login loop). The guided login **auto-picks the account named in the goal** (`acct_hint` from `_gmail_goal_scope`, so the user isn't asked "which account?" three times), asks approval, and clicks the saved-password chip + Next — but **VALET never types the password itself**; passkey/2FA hand off to the human. Rationale: recover the flow the user actually asked for while keeping the credential boundary strict. Backend Python → escalate-tier, human-reviewed PRs.
- **2026-07-20 — Bare "summarize the email" means the ONE focused message, not the inbox digest (#329)** — `_INBOX_DIGEST_RE` was catching singular "the email"/"the message" and re-reading the whole inbox. The noun is split: inbox / mass "mail" / PLURAL emails|messages (and collective "my email") claim the digest, but a SINGULAR bare "the email"/"the message" routes to `summarize_screen` via a fixed-width `(?<!the\s)` guard. Rationale: "summarize the email" almost always means the message on screen, and re-summarizing the inbox was the wrong, surprising behavior. All 40 routing tests pass.
- **2026-07-15 — Every information source follows one keyless pattern, with web research as the universal fallback (#230–#244)** — Rather than bespoke plumbing per feature, each new information source (sports, markets, news, fast lookup) reuses the same shape proven by `weather.py`: a keyless module → an `[ACTION:X]` tag added to `server.py`'s action regex AND system prompt → a self-speaking `_execute_X` handler → a `result.X` frontend card → fast-path detection gated to avoid false positives. Web research (`[ACTION:RESEARCH]`) stays as the catch-all fallback for anything a dedicated source doesn't cover. Rationale: a single, repeatable pattern makes each new source cheap to add and keeps the dispatch path uniform; gating the fast-path detection is what stops "what's the score" style phrasing from misrouting settled or conversational queries. Adding a source is: write the keyless module, register the action, wire the card, bundle the module in `packaging/valet.spec` hiddenimports. Backend Python → escalate-tier, human-reviewed PRs.
- **2026-07-15 — Prefer keyless public data sources; no new API keys, no new costs (#230–#244)** — Sports (ESPN site.api / site.web.api), markets (Yahoo Finance), news (Google News RSS), and fast lookup (DuckDuckGo Lite) all hit public, keyless endpoints. Deliberately chosen over paid data APIs so the information layer adds zero per-request cost and no new secret to manage in the proxy — consistent with the existing keyless Open-Meteo weather integration. The tradeoff accepted: these are unofficial/undocumented endpoints that can change shape, so each module owns its own parsing and degrades to the web-research fallback rather than hard-failing.
- **2026-07-15 — Answer settled facts directly; LOOKUP only for current/volatile facts; never punt (0.2.15–0.2.19)** — VALET used to either answer slowly (spinning up full web research) or punt ("I'd need to check"). Now: settled/factual questions are answered DIRECTLY with no web call, while `[ACTION:LOOKUP]` (a ~2s DuckDuckGo Lite fetch + Haiku synthesis) handles current/volatile facts. Current role-holders (coach/CEO/etc.) ALWAYS route to LOOKUP rather than answering from stale training/memory, and leadership transitions are stated precisely. Rationale: match the retrieval cost to the question — instant for things that don't change, a fast web check for things that do, and never a dead-end "I can't." The role-holder rule specifically guards against confidently stating an out-of-date name.
- **2026-07-15 — Ground on today's date and default to the current instance of a time-relative event (0.2.11)** — The system prompt injects today's date, and time-relative queries ("the World Cup", "this season", "the finals") default to the CURRENT instance instead of asking the user which year they mean. Rationale: an assistant that knows the date shouldn't make the user disambiguate the obvious; defaulting-then-confirming beats asking up front.
- **2026-07-15 — VALET remembers what it just surfaced so the user can cite it by reference (0.2.21–0.2.22)** — After presenting sports/markets/news items, VALET keeps them in `_last_shown` and injects them as a RECENTLY SHOWN context block, so "tell me more about the second one" / "open the X one" resolves to the actual item. `[ACTION:READ_ARTICLE]` opens the real article in Chrome AND speaks a summary; `[ACTION:BROWSE]` just opens it. Rationale: conversational reference ("the second one") is how people actually follow up, and it only works if the assistant holds the list it just spoke.
- **2026-07-15 — Recover a wedged WKWebView speech recognizer by rebuilding it on spaced backoff (0.2.10)** — After a full quit → relaunch, macOS hadn't released the prior process's audio session, so the WKWebView `SpeechRecognition` object came up wedged and audibly cycled the mic. The fix rebuilds the recognizer object on backoff with escalating, spaced retries rather than reusing the stuck instance — a sibling of the #218 TTS-output-after-minimize fix. Lesson: WKWebView audio/speech objects can survive into a state that only a fresh object clears, so the recovery path recreates rather than resets.
- **2026-06-25 — Compose-and-stop is the standard for ALL person-to-person messaging; VALET never auto-sends (#194/#197)** — Texts, email, and Slack messages are composed and addressed but left for the user to press send. The trigger was a real wrong-contact bug: `[ACTION:SEND] Messages` blind-typed into whatever thread was focused. The fix isn't "be more careful about focus" — it's structural: `COMPOSE_TEXT` opens a FRESH Messages compose (⌘N), addresses the named contact, accepts the autocomplete, pastes the body, and STOPS; `COMPOSE_EMAIL` opens a pre-filled Gmail compose URL and stops; `COMPOSE_SLACK` ⌘K-jumps and pastes, never pressing Enter. Rationale: an autocomplete/recipient mismatch must NEVER auto-send to the wrong person, and the few seconds the user spends glancing at the recipient chip is cheap insurance. The system prompt explicitly routes all text/email/Slack intents to these actions and warns that `SEND` (type-into-focused-app) can hit the wrong target. Body paste is clipboard ⌘V (atomic), not per-character keystrokes (which got dropped on conversation-switch and left the field empty). Backend Python → escalate-tier, human-reviewed PRs.
- **2026-06-25 — Email compose uses the Gmail `view=cm` URL, not the Gmail API; timers use VALET's built-in timer, not the Clock app (#197/#198)** — Two "use the simplest reliable mechanism" calls. (1) `COMPOSE_EMAIL` opens a pre-filled Gmail compose via the `https://mail.google.com/mail/?view=cm&fs=1&to=&su=&body=` URL — this gives a ready-to-send draft with no Gmail API (the still-deferred integration), needing only a browser logged into Gmail; the spoken name resolves to an address via contacts first. (2) Apple Clock's Timers tab has no automatable duration field (it isn't a standard text field), so timers route to VALET's own announce-when-done timer (`set_timer`) — rock-solid and hands-free — while the Clock app IS driven for stopwatch / alarms / tab-switching, which automate cleanly via buttons + ⌘-number View-menu shortcuts.
- **2026-06-25 — Clock tabs switch via ⌘-number View-menu shortcuts, not by clicking tab elements (#198)** — Live AX inspection found the Clock app's tabs are nested radio buttons whose label lives in `description` (their `name` is "missing value") with no stable container path — so clicking them by name silently failed and tab switches never happened (the timer/stopwatch landed on the wrong tab). The reliable switch is the View-menu KEYBOARD SHORTCUT: ⌘1 World Clock, ⌘2 Alarms, ⌘3 Stopwatch, ⌘4 Timers. By contrast the Start/Stop/Lap/Cancel buttons ARE text-labeled and ARE direct children of window 1, so `first button of window 1 whose name is "Start"` resolves directly. Lesson: when an AX element has no stable name/path, prefer a documented keyboard shortcut over a brittle element-path click. Alarm-setting stays best-effort because the add-alarm sheet's controls are version-specific. (Unmerged on `fix/clock-tab-shortcuts-reliable-timer`.)
- **2026-06-25 — Local dev/test builds must be signed with the SAME Developer ID + bundle id as the notarized install, or TCC revokes the grants** — Mid-session, a dev build signed with a different identity lost its Accessibility / Input Monitoring grants, so the global ⌃⌥ hotkey and keystroke automation went dead. macOS keys TCC permissions to the signed executable's identity + bundle id (`ai.valet.desktop`, team `QZX7VBLDZT`, `JAMES FINLEY UNDERWOOD`); a different signature is a different app to TCC. Fix: always codesign the test build with the production Developer ID + bundle id so the grants from the real install carry over. This is the same per-signed-executable TCC lesson behind the #136 Input-Monitoring move into the main process — re-confirmed for the dev loop.
- **2026-06-24 — Ship the menu-bar product in the public DMG; v0.2.2 supersedes v0.2.1/v0.2.0 (the Stage 4 gate is closed)** — The "everything is dev/debug-bundle only" gate that ran through every prior session is closed: the menu-bar shell + ⌃⌥ chord PTT + voice-native Raycast + guided walkthroughs ship in a signed/notarized DMG, public since v0.2.0 and now at v0.2.2. v0.2.2 is published as the `v0.2.2` GitHub release on `Kuba-Ventures/valet-downloads` (now Latest, asset `VALET_0.2.2_aarch64.dmg`); the Vercel `DOWNLOAD_URL` (project `valet-voice`, team `kuba-ventures`) was repointed for BOTH Production and Preview and production was redeployed, so www.valet-voice.com serves v0.2.2. UC4/UC6-terminal/UC5 are deliberately HELD from the signed build until the synthetic-input focus hardening + live in-app passes clear; UC1–UC3 ship. Input Monitoring is requested + surfaced in onboarding (#165). Releases are cut after on-device dogfooding via signed local reinstalls, not from `tauri dev` (which SIGABRTs on the TCC-gated Web-Speech STT).
- **2026-06-24 — The walkthrough instruction bubble is driven by a `@@VALET_CAPTION@@` stdout marker, not webview IPC (#170/#171)** — The Clicky-style instruction bubble must render on the NATIVE always-on-top cursor-follower overlay so it rides by the cursor across any app. The orb webview is served from a remote origin (localhost:8340), so its IPC can't reach Tauri app commands to update the overlay. Instead the backend prints a `@@VALET_CAPTION@@<text>` line to stdout; the Tauri host (`main.rs`) already drains the backend's stdout, so it intercepts the marker and `eval`s the caption onto the overlay window. Reuses an existing, reliable channel rather than adding a new IPC surface across the origin boundary. Also fixed the navigation-step stall in the same pass: the completion baseline was snapshotted AFTER the pane opened, so navigation steps could never complete — snapshot it before. Plus narrate-first (no dead air), completion via a system-state check (`Step.system_check`; dark-mode checks `defaults read -g AppleInterfaceStyle`), and the bubble on every step (#172); and the walkthrough planner moved Sonnet→Haiku (`claude-haiku-4-5`) to cut the planning wait, curated walkthroughs skipping planning entirely (#173). Backend Python + Rust → escalate-tier, human-reviewed PRs.
- **2026-06-22 — Duplicate licenses fixed at the DB layer with an atomic upsert + UNIQUE index, not application-level locking (branch `fix/vip-duplicate-licenses`)** — A single signup fires several Stripe events near-simultaneously (`customer.subscription.created`/`.updated`, `checkout.session.completed`, and the success page hitting the same path), and `upsertLicenseFromSubscription` did a read-then-insert — every concurrent SELECT found no row, so each INSERTed, yielding 2–3 duplicate "Ultra · Active" rows per subscription. Rejected app-side mutexes/queues (fragile across serverless invocations); chose to make the database the source of truth: an atomic `INSERT … ON CONFLICT DO NOTHING` keyed on `stripe_subscription_id`, then a key-preserving UPDATE + readback, so concurrent callers collapse to ONE row and the license key is generated once and never rotated. `migration_dedupe_licenses.sql` first collapses existing duplicates (keep claimed-account → most-used → oldest; dropped dupes have 0 usage and their `license_usage` cascades) then adds a partial UNIQUE index on `stripe_subscription_id`. **Ordering invariant: the migration must run before/with the deploy** because the upsert's `ON CONFLICT` target depends on that index. Touches billing → escalate-tier, human-reviewed PR.
- **2026-06-22 — The PTT status pill becomes a single "Always listening" toggle; the tray dropdown becomes a custom white webview popover (#160 / #158)** — Two UI calls. (1) The top-right green "PUSH-TO-TALK"/"Sleeping" pill was dim (40%-opacity purple) and redundant — push-to-talk is the ⌃⌥ chord and always works — so it's replaced by one obviously-toggleable "Always listening" switch; the orb stays bright in both states (off = "ready", not asleep). (2) The macOS status-bar NSMenu follows system appearance (dark in Dark Mode) with no supported way to force it white, and Tauri 2 seals the NSMenu handle — so the native dropdown was replaced with our own borderless webview popover (`loading/tray-menu.html`), styled white unconditionally and anchored under the tray icon, items routed through a new `tray_action` command into the same handler the native menu used. Frontend + Rust → human-reviewed PRs.
- **2026-06-21 — Settings information architecture: app surfaces aligned to the three-surface IA (branch `feat/settings-ia`)** — One source of truth per setting across web account (identity/billing/license — owns), in-app panel (per-machine config the app validates/applies), and menu bar (status + toggles + links, never a form).
